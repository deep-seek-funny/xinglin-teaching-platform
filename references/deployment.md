# 部署与运行（脱敏版）

> 只记录形态与流程约束；主机、口令、端口、进程名、文件路径一律不写入。

## 一、本地运行

- Node.js ≥ 20，CommonJS；无前端构建步骤，页面由服务直接提供。
- 入口是单个服务文件；端口用环境变量覆盖，默认 3000。
- 依赖较少：实时语音用 WebSocket 库，知识文件解析用文档解析库，核型检测依赖可选运行时（缺失时该模块自动跳过）。
- 静态服务会把应用根目录整体暴露，这是"免构建"的取舍：**根目录不要放密钥、备份、隐私数据**。
- 语法检查只能证明能解析；页面内联脚本与 iframe 子应用必须真浏览器验证。

## 二、生产拓扑（四进程 + 反向代理）

```
公网 443（TLS）
└─ 反向代理
   ├─ 主路径            → 主应用（页面 + API + 全部子应用）
   ├─ 子路径 1          → PBL 独立服务（独立数据目录）
   └─ 子路径 2          → 独立小站点（系统服务托管）
可选：本地声纹服务（Python），仅供 PBL 调用
```

- 主应用与 PBL 用进程管理器托管；独立小站点走系统服务。两类托管方式混用，改动前先确认当次生效的是哪一个。
- TLS 由反向代理或主应用的 TLS 进程承担，二者择一。
- 反向代理对部分接口有单独限流/超时配置；改路由要同步代理配置，否则表现为"本地正常、线上超时"。
- 子路径部署要求前端接口用**相对路径**，不能写死绝对地址。

## 三、数据与备份

- 运行数据全部在数据目录：账号、学生档案、病例与知识库、图谱定义、通知、音频。
- 主应用启动后自动跑一次备份，之后按日备份；保留天数由配置控制（当前实现有缺陷，见已知问题）。
- 备份是整目录快照；恢复必须先比对差异并备份现状，不能拿旧快照直接覆盖线上。
- 学生档案存在"历史全量数组"与"每生一档"两代结构并存，改结构前先确认当前生效的是哪种。

## 四、发布流程（最小步骤）

1. 在服务器上建带时间戳的备份目录，备份将被覆盖的代码与全部运行数据。
2. 只上传代码白名单（主服务、页面、模块目录），**不覆盖**数据目录、配置文件、提示词文件。
3. 远端做语法检查；页面标记用抓取 + 文本匹配验证（新加的 DOM 标识或函数名）。
4. 重启对应进程，等待数秒后检查健康接口与一个真实业务接口。
5. 前端改动必须硬刷新验证——旧页面仍在内存里跑旧代码，容易误判"没生效"。
6. 失败即停：不自动重试覆盖，报告备份路径与失败原因。

## 五、已知风险（代码层面存在，不要当作已修复）

| 风险 | 表现 | 处理原则 |
|---|---|---|
| 根目录整体静态暴露 | 根目录文件可能被直接访问 | 不在根目录放敏感文件 |
| 消息桥未校验来源 | 子应用间消息可被任意页接收 | 补目标源与来源校验 |
| 同步文件读写 | 高并发写放大、无事务 | 写路径合并；读失败不得用空数据覆盖 |
| 配置文件含密钥 | 泄露即失控 | 不入库、不进技能、不截图；用环境变量覆盖 |
| 学生数据敏感 | 音频、对话、姓名 | 对外演示用匿名数据，导出前脱敏 |
