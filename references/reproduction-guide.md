# 复现指南：从零搭一套同样的教学平台

> 目标读者：会一点 Node.js、能读 JSON、没有 AI 应用经验。
> 目标：按本文顺序，2–3 周做出一个最小可用闭环，再逐个加模块。
> 本文中的接口路径是**参考设计**（复现时自行命名），不是某个生产站点的真实路径。

## 0. 先想清楚三件事

1. **一个能力点**：不要整门课。例："能向孕妇解释 21 三体的风险"。
2. **怎么算学会**：可观测的动作 + 判定规则（量规、关键词、结构）。
3. **留下什么证据**：谁、何时、第几次、原话、评分、版本。

先写一页规则卡（见 `assets/templates/rule-card.md`），写不出来就不要开始写代码。

## 1. 技术选型（最小依赖）

| 层 | 选择 | 理由 |
|---|---|---|
| 服务 | Node.js ≥ 20 + Express 5（或原生 http） | 单文件可跑，无需构建 |
| 页面 | 单个 HTML + 内联脚本，或原生 ES module | 免打包，改完刷新即生效 |
| 数据 | JSON 文件（临时文件 + rename 原子写） | 零运维；数据量 >10 万条再换 SQLite |
| 模型 | DeepSeek（OpenAI 兼容）；语音可选豆包 | 文本一个 Key 就能跑；语音后加 |
| 部署 | 1 台云服务器 + 反向代理 + 进程管理器 | 单实例，别开多进程 |

依赖建议：`express`、`ws`（实时语音才需要）、`mammoth`/`pdf-parse`（要传知识文件时）。不要一上来上数据库、Redis、微服务。

## 2. 目录结构（照抄即可）

```
app/
├─ server.js              入口：鉴权、路由挂载、静态服务
├─ config/
│  └─ models.json         模型连接（Key 用环境变量，不写文件）
├─ data/                  运行数据（不进版本库）
│  ├─ users.json          账号（教师/学生）
│  ├─ profiles/           <hash>.json 每人一档
│  ├─ diseases.json       病例 + 量规 + 提示词
│  └─ logs/YYYY-MM-DD.jsonl  证据日志（追加写）
├─ modules/
│  ├─ sim.js              问诊：对话 + 评分
│  ├─ eval.js             提示词评估
│  ├─ graph.js            图谱：配置 + 学生状态 + 建造评分
│  ├─ diagnosis.js        自检：作答 + 错因 + 复习规划
│  └─ stats.js            看板与导出
├─ public/
│  ├─ index.html          主界面（视图切换）
│  └─ modules/            各子应用（可 iframe）
└─ lib/
   ├─ store.js            读/写 JSON（原子写 + 冲突检测）
   ├─ auth.js             签名令牌、角色
   └─ llm.js              模型调用封装（超时、JSON、重试）
```

## 3. 六个阶段（每阶段都有验收物）

### 阶段 0（1–2 天）：规则卡 + 数据骨架

- 写 `rule-card.md`：任务名 / 能力点 / 学生动作 / 系统反馈 / 判法 / 证据字段 / 失败处理 / 验收方式。
- 建 `data/` 空文件：`users.json`、`diseases.json`、`profiles/`、`logs/`。
- 验收：能对同事讲清"学生做什么、系统怎么判、留下什么"。

### 阶段 1（3–5 天）：最小闭环

服务端三个函数就够：

```js
// 1) 组装提示：病例事实 + 教学约束 + 学生输入
function buildMessages(disease, history, userText) { /* ... */ }

// 2) 调模型（超时 + JSON 模式 + 错误处理）
async function chat(messages) { return llm(messages, { json: false, timeout: 60000 }); }

// 3) 写记录（原子，返回新版本号）
function saveRecord(key, record) { return store.append(key, "sims", record); }
```

页面：一个输入框 + 对话列表 + "结束并评分"按钮。
评分：先用规则（关键词覆盖）跑通，再接模型四评委。
验收：3–5 名学生能独立完成一次；记录里能追到原话与时间。
坑：模型返回不是合法 JSON 时，**退化为纯文本**而不是 500；超时要有前端提示。

### 阶段 2（3–5 天）：数据留痕 + 教师可见

- 统一记录结构（见 `data-and-scoring.md` 与 `assets/templates/records.example.json`）。
- 写日志 `logs/YYYY-MM-DD.jsonl`：模型原始返回、耗时、输入摘要。
- 教师页：按班/按人列表，点开看单条记录（原话、评分、依据）。
- 验收：任意学生任意一次训练都能追到原始记录；导出 CSV 能打开不乱码。

### 阶段 3（5–7 天）：第二个模块，验证"可复用"

- 选一个结构不同的模块（问答 → 图谱/自检），复用同一套"配置 + 记录 + 日志 + 评分"。
- 学生会话状态单独存（不要塞进主档案的通用字段）。
- 验收：同一套鉴权、同一套记录格式、同一套看板能用；新增第二个模块时**没有改第一个模块的代码**。

### 阶段 4（5–7 天）：评分可信 + 查重

- 评分类任务：`temperature=0`、JSON 输出、要求引用原文依据；空分与解析失败分开处理（失败不记 0 分）。
- 查重：短文本用 n-gram 集合相似度（见 `algorithms.md`），命中拒绝并记日志。
- 分数口径写进文档（哪项权重、怎么归一化），不要只存在代码里。
- 验收：同一份输入重复提交，分数稳定；抄袭样本被拒且可复核。

### 阶段 5（5–7 天）：个性化路径 + 看板

- 证据 → 短板（练过但没成型）→ 任务卡（任务/时限/验收）→ 学生端呈现 → 完成情况回写。
- 看板：班级覆盖、异常名单、分模块趋势；**区分活动指标与效果指标**。
- 验收：每条建议都有任务、有时限、有验收；能回答"这版改完，哪项行为变了"。

## 4. 关键实现点（最容易翻车）

| 点 | 做法 |
|---|---|
| 原子写 | 写 `file.tmp.<pid>` → `rename` 覆盖；写前读旧值，比较后再写 |
| 并发冲突 | 记录带 `revision`，客户端提交 `baseRevision`，不一致返回 409 |
| 模型超时 | 每类任务单独设超时（对话 60s / 评分 180s / 长评估 600s） |
| JSON 输出 | 提示词里出现 "json" + `response_format: json_object`；仍失败则文本兜底 |
| 音频 | 单独目录 + 文件名校验 + 大小上限；只允许本人读取 |
| 权限 | 令牌签名 + 课程/角色中间件；**不要在鉴权之前挂任何路由** |
| 密钥 | 环境变量；配置文件加入忽略清单；日志不打印 Key |
| 演示数据 | 独立开关 + 页面水印；导出时排除 |

## 5. 上线检查清单

- [ ] 单实例运行（进程管理器只起 1 个 worker）
- [ ] 反向代理：主站、子应用、静态资源三类规则；大文件/长请求单独放宽超时
- [ ] TLS 证书自动续期
- [ ] 每日备份（数据目录整体快照），恢复流程演练过一次
- [ ] 健康检查接口 + 一个真实业务接口的冒烟测试
- [ ] 隐私：学生姓名/学号/音频导出前匿名化
- [ ] 日志保留期与清理策略

## 6. 复现到什么程度算成功

- 一名学生能完成一次训练，教师能看到原话与评分依据。
- 教师改一条量规/提示词，学生端下次训练立刻生效（不需要改代码）。
- 你能在一小时内给第二个模块接上同一套记录与看板。
- 你能说清每个分数的来源与局限。
